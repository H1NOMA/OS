# Как устроена Hiko OS

Честно и по делу: что значит «настоящая операционная система» и как это сделано.

## Никто не пишет ОС ядром с нуля

Полноценная ОС — это не только «рабочий стол». Это загрузчик, ядро (управление
памятью, процессами, драйверы для тысяч устройств), файловые системы, сеть, звук,
графика. Написать это с нуля — годы работы целой команды. Поэтому **все** современные
«новые ОС» строятся на готовом ядре:

| Система | Ядро | Своя оболочка |
|---|---|---|
| ChromeOS | Linux | да |
| SteamOS | Linux (Arch) | да (Gamescope + Steam) |
| Android | Linux | да |
| webOS (LG) | Linux | да (веб-оболочка) |
| **Hiko OS** | **Linux** | **да (оболочка Hiko)** |

Hiko OS честно называет вещи своими именами: это **Linux-дистрибутив, вся оболочка
которого — Hiko**. Для тебя как пользователя это отдельная система: включаешь
компьютер, выбираешь Hiko в меню загрузки, попадаешь на рабочий стол Hiko. Windows
и браузер не участвуют.

## Цепочка загрузки

```
Питание
  → прошивка (UEFI/BIOS)
    → загрузчик GRUB  ← здесь выбор: Hiko OS или Windows (dual-boot)
      → ядро Linux + initramfs
        → systemd
          → greetd (автовход владельца, без пароля)
            → cage (Wayland-компоновщик: одно окно во весь экран)
              → Chromium --kiosk --app  (движок, скрыт)
                → Hiko  ← рабочий стол, окна, приложения, Ави
```

Ключевой момент: пользователь **не видит браузер**. `cage` показывает ровно одно
приложение на весь экран без панелей, вкладок и адресной строки, а Chromium в
режиме `--kiosk --app` — это просто движок, отрисовывающий оболочку. С точки зрения
человека за экраном это цельная система, а не «сайт в браузере».

## Почему движок — Chromium

Оболочка Hiko уже написана на веб-технологиях (это её сильная сторона: единый файл,
мгновенные правки, ноль зависимостей). Чтобы она стала системной оболочкой, нужен
движок, который её рисует. Chromium выбран потому, что умеет всё, что нужно Hiko:

- **Web Speech API** — голос и слух ассистента Ави;
- **file://** + постоянный профиль — хранилище всей системы (файлы, настройки, виджеты);
- встраивание сайтов и работа обхода блокировок в Браузере Hiko;
- аппаратное ускорение графики через Wayland.

Движок скрыт полностью — это деталь реализации, как для Windows деталь то, что её
интерфейс рисует DWM.

## Что где лежит в системе

| Путь | Что это |
|---|---|
| `/opt/hiko/Hiko.html` | Оболочка Hiko (собирается из исходников репозитория) |
| `/usr/local/bin/hiko-session` | Запуск оболочки: `cage` + Chromium в kiosk |
| `/usr/local/bin/hiko-install` | Установка системы на диск с dual-boot |
| `/etc/greetd/config.toml` | Автовход владельца в оболочку при старте |
| `~/.hiko/chromium` | Профиль = хранилище системы (переживает перезагрузки) |

## Оболочка vs система

- **Оболочка** (этот репозиторий, `js/`, `css/`, `index.html`) — рабочий стол,
  оконный менеджер, приложения, ассистент. Разрабатывается и правится как обычно,
  собирается в один `Hiko.html` командой `python3 tools/build.py`.
- **Система** (`distro/`) — тонкий слой, который превращает оболочку в загрузочную
  ОС: ядро, автологин, kiosk-сессия, установщик. Собирается в `.iso` командой
  `./distro/build.sh`.

Обновить оболочку на установленной системе можно, не переустанавливая ОС —
достаточно заменить `/opt/hiko/Hiko.html`.

## Границы честности

- Это **не** ОС с собственным ядром — и не должна ею быть; так не делает никто.
- Собрать финальный `.iso` нужно на Linux-машине (или в Docker) — это нормально
  для сборки любого дистрибутива, свой Linux при этом ставить не требуется.
- Установщик на диск (`hiko-install`) ставит систему на **отдельный диск** целиком;
  установку на тот же диск, что и Windows (с ужиманием раздела), безопаснее делать
  вручную — она намеренно не автоматизирована.

Сборка, запись, загрузка и dual-boot — [distro/README.md](../distro/README.md).
