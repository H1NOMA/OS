# Hiko OS — сборка загрузочной системы

Здесь живёт то, что превращает Hiko из «страницы» в **настоящую операционную
систему, в которую загружается компьютер** — наравне с Windows и Linux.

## Что это на самом деле

Никто не пишет ОС «с нуля ядром» за разумное время — так не делают даже большие
компании. ChromeOS, SteamOS, webOS, Android — это **ядро Linux + собственная
оболочка** сверху. Hiko OS устроена так же:

```
┌───────────────────────────────────────────────┐
│  Оболочка Hiko  (весь рабочий стол, приложения) │  ← это ты видишь
├───────────────────────────────────────────────┤
│  Chromium в режиме приложения (kiosk)           │  ← движок, скрыт
│  cage (Wayland-компоновщик, одно окно во весь   │
│        экран, без панелей и рамок)              │
├───────────────────────────────────────────────┤
│  greetd (автовход) · PipeWire (звук) ·          │
│  NetworkManager (сеть)                          │
├───────────────────────────────────────────────┤
│  Ядро Linux + systemd                           │  ← железо, драйверы
└───────────────────────────────────────────────┘
```

Пользователь **не видит браузер**: при включении компьютера сразу появляется
загрузочное меню, выбираешь Hiko OS — и через пару секунд перед тобой рабочий стол
Hiko на весь экран. Это отдельная система, а не программа внутри Windows.

## Собрать образ (.iso)

Нужен только **Docker** (Windows/macOS — Docker Desktop, Linux — пакет docker).
Свой Arch/Linux ставить не надо — сборка идёт в контейнере.

```bash
./distro/build.sh
```

Результат: `distro/out/hiko-*.iso`.

> Почему в контейнере? Образ ОС собирается инструментом `mkarchiso` из пакетов
> Arch Linux и требует прав на монтирование (`--privileged`). Это стандартный
> способ собирать загрузочные образы — на любой ОС через Docker.

### Что ты увидишь при сборке (это норма)

Сборка проверена целиком: получается загрузочный образ ~2 ГБ
(`ISO 9660 … (bootable)`, BIOS + UEFI). По ходу мелькнут два сообщения — так и должно быть:

- `customize_airootfs.sh is deprecated` — предупреждение archiso. Скрипт настройки
  системы (пользователь, автологин, сервисы) сейчас работает; это задел на будущее,
  если archiso однажды уберёт этот механизм.
- `greetd/config.toml installed as …config.toml.pacnew` — значит **наш** конфиг
  автологина сохранён, а дефолт пакета отложен в `.pacnew`. Именно это и нужно.

## Записать на флешку

Флешка от 4 ГБ. Любой способ:

- **balenaEtcher** (проще всего, Windows/macOS/Linux) — выбрать `hiko-*.iso` и флешку.
- **Rufus** (Windows) — режим записи **DD Image**.
- Терминал (Linux/macOS):
  ```bash
  sudo dd if=distro/out/hiko-*.iso of=/dev/sdX bs=4M status=progress oflag=sync
  ```
  (`/dev/sdX` — твоя флешка; проверь `lsblk`, чтобы не перепутать диск!)

## Загрузиться

1. Вставь флешку, включи/перезагрузи компьютер.
2. Открой меню загрузки (обычно `F12`, `F9`, `Esc` или `F2` при старте — зависит от
   материнской платы) и выбери флешку.
3. Hiko OS стартует сразу на весь экран. Ничего устанавливать не обязательно —
   в live-режиме уже всё работает (данные сохранятся, только пока не установишь на диск).

> UEFI: если флешка не грузится, отключи **Secure Boot** в настройках BIOS/UEFI
> (образ не подписан ключами Microsoft). Legacy/BIOS-режим тоже поддержан.

## Установка на диск (dual-boot с Windows)

Это и есть «наравне с Windows»: ставишь Hiko на **отдельный диск**, а при включении
ПК выбираешь в меню GRUB — Windows или Hiko.

1. Загрузись с флешки (Hiko live).
2. Нажми `Ctrl+Alt+F2` — попадёшь в текстовую консоль.
3. Войди: `hiko` / `hiko`.
4. Запусти установку:
   ```bash
   sudo hiko-install
   ```
5. Скрипт покажет список дисков. Укажи **отдельный** диск для Hiko (не тот, где
   Windows) и подтверди. Он разметит диск, поставит систему и настроит GRUB.
6. `os-prober` найдёт Windows на другом диске и добавит его в меню загрузки.
7. Перезагрузись, вынь флешку — при включении появится меню: **Hiko OS** и **Windows**.

> Установщик стирает **выбранный диск целиком**. Он не трогает другие диски —
> поэтому Windows на своём диске остаётся цел. Ставить Hiko на тот же диск, что и
> Windows (ужимая раздел), можно, но это ручная операция — здесь не автоматизирована,
> чтобы случайно не задеть данные.

## Данные и обновление

- Файлы, настройки, виджеты и установленные приложения хранятся в профиле оболочки
  (`~/.hiko`) на диске Hiko и переживают перезагрузки.
- Резервная копия: **Настройки → Данные → Экспортировать** (один JSON со всей системой).
- Обновить оболочку без переустановки системы: собери новый `Hiko.html`
  (`python3 tools/build.py`) и замени `/opt/hiko/Hiko.html` на диске Hiko.

## Логины по умолчанию

`hiko` / `hiko` (и `root` / `hiko`). Смени пароль после установки: `passwd`.

## Аппаратные заметки

- Голос Ави, погода и обход блокировок требуют интернета — подключи сеть
  (в live: `nmtui` в консоли; на установленной системе — обычная сеть Linux).
- На виртуалке для проверки: включи UEFI и, при чёрном экране графики,
  добавь в `hiko-session` флаг `--disable-gpu` (программный рендер).
